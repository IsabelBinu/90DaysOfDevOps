## 1. Core Directories (Must Know)

### 1. `/` – Root Directory

**Purpose:** The top-level directory in Linux. Every other file and directory exists under `/`.

ls -l /

**Example contents:**
- `home` – Contains user home directories.
- `etc` – Contains system configuration files.

**I would use this when:** Navigating the Linux filesystem or locating important system directories.

### 2. `/home` – User Home Directories

**Purpose:** Stores personal directories for regular Linux users, including their documents, scripts and configuration files.

ls -l /home

**Example contents:**
- `ubuntu` – Default user home directory on many Ubuntu EC2 instances.
- `devops-user` – Home directory of a user created for practice.

**I would use this when:** Managing user files, scripts and personal working directories.

### 3. `/root` – Root User's Home Directory

**Purpose:** The home directory of the root (administrator) user. It stores root-specific files and configurations.

sudo ls -l /root

**Example contents (hidden files):**
- `.bashrc` – Bash shell configuration.
- `.profile` – Login environment configuration.

To view hidden files:

sudo ls -la /root


**I would use this when:** Troubleshooting the root user's environment or managing administrator-specific configurations.

### 4. `/etc` – Configuration Files

**Purpose:** Contains system-wide configuration files for Linux services, networking, users and applications.

ls -l /etc

**Example contents:**
- `passwd` – Contains user account information.
- `hosts` – Maps hostnames to IP addresses.

**I would use this when:** Configuring services such as Nginx, SSH or networking.

### 5. `/var/log` – System Logs

**Purpose:** Stores log files generated by applications and system services. These logs help diagnose errors and monitor system activity.

ls -l /var/log

**Example contents:**
- `nginx` – Directory containing Nginx access and error logs.
- `apt` – Directory containing package management logs.

**I would use this when:** Investigating service failures, application errors or unexpected server behaviour.

### 6. `/tmp` – Temporary Files

**Purpose:** Stores temporary files created by applications and users. Its contents may be automatically deleted during system cleanup or reboot.

ls -l /tmp

**Example contents:**
- `node-compile-cache` – Temporary Node.js compilation cache.
- `default.pa` – A configuration file present in the example environment.

**I would use this when:** Creating temporary files or directories while testing scripts and troubleshooting applications.

---



### 7. `/bin` – Essential Commands

**Purpose:** Traditionally contains essential Linux commands required for basic system operations. On modern Ubuntu systems, `/bin` is usually a symbolic link to `/usr/bin`.

ls -l /bin

**Example contents:**
- `ls` – Lists directory contents.
- `cp` – Copies files and directories.

To see the binaries inside:

ls -l /bin/

**I would use this when:** Finding essential Linux commands or verifying their executable files.

### 8. `/usr/bin` – Application and System Commands

**Purpose:** Contains executable programs and command-line utilities installed as part of Linux or through package management.

ls -l /usr/bin

**Example contents:**
- `bash` – Bash command interpreter.
- `ls` – Lists files and directories.

**I would use this when:** Locating installed command-line programs or troubleshooting executable paths.

### 9. `/opt` – Optional Applications

**Purpose:** Commonly used to store optional or third-party software installed separately from the standard Linux directory structure.

ls -l /opt

**Example contents:**
- `imagemagick` – Directory for image-processing software in the example environment.
- `nvm` – Directory associated with Node Version Manager.

**I would use this when:** Installing or managing third-party applications that are kept separate from standard system packages.


Part 2

Scenario 1: Service not Starting

1. systemctl status nginx - Check whether the status is running, stopped or failed.
2. systemctl is-enabled nginx - Check whether the app is enabled.
3. journalctl -u myapp -n 50 - Displays the 50 journal entries 
4. systemctl cat nginx - Displays the systemd unit configuration, including the command used to start the application

Scenario 2: High CPU Usage

1. top - Displays the live CPU usage, memory usage and running processes.
2. ps aux --sort=-%cpu | head -10 - Displays the top CPU-consuming processes, sorted from highest to lowest.
3. ps -o pid,pcpu,pmem,comm -p 2 - Displays CPU usage, memory usage and the command name for process ID 2.
4. free -h -  Checks available and consumed system memory to determine whether memory pressure could also be affecting performance.

Scenario 3: Finding Service Logs

1. systemctl status ssh - checks service status
2. journalctl -u ssh -n 50 - Displays the latest 50 journal entries associated with the ssh service.
3. journalctl -u ssh -f - Continuously displays new log entries generated by the ssh service.(real time)

Scenario 4: File Permissions Issue
1. ls -l /home/test-user - For checking current permissions
2. chmod +x /home - Add execute permission
3. ls -l - Verify it worked
